# CS361 Electronic Mailbox & Document Flow System
# Project Definition

ระบบ e-Mailbox สำหรับรับ ลงทะเบียน จัดเก็บ และกระจายเอกสารอิเล็กทรอนิกส์ภายในหน่วยงาน โดยมีเป้าหมายเพื่อช่วยให้การจัดการเอกสารเป็นระบบมากขึ้น ลดปัญหาเอกสารสูญหายหรือล่าช้า และช่วยให้สามารถติดตามการดำเนินงานของเอกสารได้อย่างชัดเจน

# Primary User: เจ้าหน้าที่ที่รับ ลงทะเบียน และกระจายเอกสาร

# Project Vision

สร้างระบบ e-Mailbox สำหรับรับ ลงทะเบียน จัดเก็บ และกระจายเอกสารอิเล็กทรอนิกส์แบบครบวงจร รองรับการทำงานตาม Workflow การติดตามสถานะ การกำหนด Deadline และการตรวจสอบข้อมูลย้อนหลังของเอกสาร เพื่อให้การจัดการเอกสารมีความเป็นระบบ โปร่งใส และสามารถตรวจสอบย้อนหลังได้

# V1 – Information Service

V1 ทำหน้าที่เป็น Information Service ที่อนุญาตให้ผู้ใช้งานเข้าถึงและเรียกดูข้อมูลพื้นฐานเกี่ยวกับประเภทเอกสาร ช่องทางการรับและส่งเอกสาร ขั้นตอนการดำเนินงาน และข้อมูลที่จำเป็น โดยไม่ต้องเข้าสู่ระบบ

**V1 Direction**

สำหรับ V1 ระบบจะเน้นการให้ข้อมูลพื้นฐานเกี่ยวกับเอกสาร เพื่อให้ผู้ใช้สามารถตรวจสอบข้อมูลที่จำเป็นสำหรับการรับและส่งเอกสารได้ง่าย

**V1 Scope**

• ดูประเภทและหมวดหมู่ของเอกสาร

• ดูช่องทางในการรับและส่งเอกสาร

• ดูขั้นตอนพื้นฐานในการดำเนินงาน

• ดูข้อมูลที่จำเป็นสำหรับการส่งเอกสาร

• ค้นหาข้อมูลพื้นฐาน เช่น ประเภทเอกสารหรือขั้นตอน

• เข้าถึงข้อมูลพื้นฐานได้โดยไม่ต้องเข้าสู่ระบบ

# Boundary

**Goal**

กำหนดขอบเขตความรับผิดชอบของระบบรับและกระจายเอกสารอิเล็กทรอนิกส์ใน V1 พร้อมระบุผู้ใช้งาน ระบบภายนอก แหล่งข้อมูล และการไหลของข้อมูลเข้าและออกจากระบบ

**Inside the System**

• การแสดงประเภทและหมวดหมู่เอกสาร

• การแสดงช่องทางการรับและส่งเอกสาร

• การแสดงขั้นตอนพื้นฐานในการดำเนินงาน

• การแสดงข้อมูลที่จำเป็นสำหรับการส่งเอกสาร

• การจัดหมวดหมู่ข้อมูลเพื่อให้ผู้ใช้เข้าถึงได้ง่าย

• การค้นหาข้อมูลพื้นฐานเกี่ยวกับเอกสารและขั้นตอน

**Outside the System**

• การเข้าสู่ระบบของผู้ใช้

• การกำหนดสิทธิ์ในการเข้าถึงเอกสาร

• การลงทะเบียนและรับเอกสารจริง

• การกระจายหรือมอบหมายเอกสาร

• การติดตาม Deadline ของเอกสาร

• ระบบ Inbox

• การจัดการ Workflow หลายขั้นตอน

• Audit Trail และการตรวจสอบประวัติการดำเนินงานแบบเต็มรูปแบบ

**External Actors**

**เจ้าหน้าที่รับเอกสาร**

หากมีการเปิดให้บุคคลทั่วไปเข้าดูข้อมูลโดยไม่ Login สามารถพิจารณาเพิ่มผู้ส่งเอกสารหรือผู้ใช้งานทั่วไปเป็น External Actor ได้

**External Systems / Data Sources**

• ฐานข้อมูลเดิม

• คู่มือหรือระเบียบปฏิบัติงานของสาขาวิชา

• เอกสารหรือข้อมูลที่ใช้เป็นแหล่งอ้างอิงของประเภทและขั้นตอนการส่งเอกสาร

**Exact Source of Truth: TO VALIDATE**

# Boundary Flows

**External Data Source → System**

• ข้อมูลประเภทและหมวดหมู่ของเอกสาร

• รายละเอียดขั้นตอนการดำเนินงาน

• ข้อมูลช่องทางการติดต่อและส่งเอกสาร

• ข้อมูลที่จำเป็นสำหรับการส่งเอกสาร

**User → System**

• คำค้นหาหรือคำที่ใช้ค้นหาข้อมูล

• การเลือกหมวดหมู่เอกสาร

• การเลือกประเภทเอกสาร

• การเรียกดูรายละเอียดของเอกสารหรือขั้นตอนที่สนใจ

**System → User**

• รายการหมวดหมู่เอกสาร

• ผลการค้นหา

• รายละเอียดขั้นตอนการดำเนินงาน

• ช่องทางการรับและส่งเอกสาร

• รายการข้อมูลหรือเอกสารที่ต้องเตรียม

# Data Ownership / Source of Truth

ข้อมูลประเภทเอกสาร ขั้นตอนการดำเนินงาน และระเบียบที่เกี่ยวข้องไม่ได้ถูกสร้างขึ้นใหม่ทั้งหมดโดยระบบ V1 แต่ควรอ้างอิงจากข้อมูลหรือเอกสารที่สาขาวิชามีอยู่แล้ว

Source of Truth อาจอยู่ในรูปแบบ Spreadsheet, เอกสารข้อความ, คู่มือ หรือระบบ/API ที่มีอยู่เดิม

**Exact Source of Truth: TO VALIDATE**

# Assumptions

• ข้อมูลพื้นฐานของเอกสารและขั้นตอนการดำเนินงานมีการเตรียมไว้ในระบบ

• ผู้ใช้สามารถเข้าดูข้อมูล V1 ได้โดยไม่ต้องเข้าสู่ระบบ

• ผู้ใช้ต้องการข้อมูลที่ชัดเจนเกี่ยวกับการรับและส่งเอกสาร

• ประเภทเอกสารและช่องทางการรับส่งมีข้อมูลที่สามารถแสดงให้ผู้ใช้ตรวจสอบได้

• ขั้นตอนและข้อมูลที่จำเป็นสำหรับการส่งเอกสารสามารถกำหนดไว้ล่วงหน้าได้

# To Validate

• ผู้ใช้ต้องการดูข้อมูลประเภทเอกสารอะไรบ้าง?

• ผู้ใช้ต้องการทราบช่องทางการรับและส่งเอกสารแบบใด?

• ผู้ใช้เข้าใจขั้นตอนการดำเนินงานจากข้อมูลที่ระบบแสดงหรือไม่?

• ข้อมูลอะไรบ้างที่ผู้ใช้จำเป็นต้องรู้ก่อนส่งเอกสาร?

• ผู้ใช้สามารถเข้าถึงข้อมูลที่ต้องการได้โดยไม่ต้องเข้าสู่ระบบหรือไม่?

• ปัจจุบันข้อมูลประเภทเอกสาร ขั้นตอน และระเบียบปฏิบัติงานถูกจัดเก็บไว้ที่ไหนและอยู่ในรูปแบบใด?

• ข้อมูลเหล่านี้มีการปรับปรุงหรือเปลี่ยนแปลงบ่อยแค่ไหน?

• ใครเป็นผู้รับผิดชอบในการตรวจสอบและอัปเดตข้อมูล?

• ข้อมูลขั้นตอนในปัจจุบันมีความชัดเจนเพียงพอที่จะนำมาแสดงให้ผู้ใช้เข้าใจได้ทันทีหรือไม่?

• มีข้อมูลใดบ้างที่ไม่ควรเปิดให้ผู้ใช้ทั่วไปเข้าถึงโดยไม่ต้องเข้าสู่ระบบ?

# Grill Questions / Challenges

• ถ้ามีข้อมูลจำนวนมาก ระบบจะช่วยให้ผู้ใช้ค้นหาข้อมูลที่ต้องการได้อย่างไร?

• ผู้ใช้ต้องการติดตามสถานะเอกสารในระดับไหนบ้าง?

• ข้อมูลประเภทใดควรเปิดให้ผู้ใช้เข้าถึงได้โดยไม่ต้องเข้าสู่ระบบ?

• หากข้อมูลประเภทเอกสารหรือขั้นตอนการดำเนินงานมีการเปลี่ยนแปลง ใครจะเป็นผู้รับผิดชอบในการอัปเดตข้อมูล?

# V1 Boundary Summary

**In Scope**

V1 ครอบคลุมการให้ข้อมูลพื้นฐานเกี่ยวกับเอกสารและขั้นตอนการดำเนินงาน รวมถึงการค้นหาข้อมูลดังกล่าว โดยไม่ต้องเข้าสู่ระบบ

**Out of Scope**

V1 ยังไม่ครอบคลุมการจัดการเอกสารจริง เช่น การรับและลงทะเบียนเอกสาร การกระจายเอกสาร การติดตามสถานะ การจัดการสิทธิ์ Workflow หลายขั้นตอน Deadline, Inbox และ Audit Trail
